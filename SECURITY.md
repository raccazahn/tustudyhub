# Security Policy

## Reporting
Do not publish exploitable details or credentials in a public issue. Report suspected vulnerabilities privately to the project lead and lecturer using the contact method they approve. Add the approved contact method here when confirmed.

Include a short description, affected component, safe reproduction steps, impact, and suggested mitigation where known.

## Expectations
- Never commit passwords, API keys, tokens, private keys or production environment files.
- Never commit real student data or unauthorized copyrighted examination materials.
- Hash passwords, validate inputs and enforce least privilege.
- Validate uploaded file types and sizes and apply server-side protections.
- Use HTTPS, maintain backups, test restoration, and review security-sensitive changes.
- Keep secrets out of logs, screenshots, issues and AI prompts.

## Incident response
Restrict access, preserve relevant logs safely, rotate exposed credentials, fix and test the issue, inform the lecturer/project owner as appropriate, and record preventive actions.
