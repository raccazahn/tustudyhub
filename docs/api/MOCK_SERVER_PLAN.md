# API Mock Server Plan

The concept paper recommends an API-first workflow and permits mock responses so frontend work can proceed before backend implementation is complete.

## Before coding
- [ ] Agree endpoint method/path, purpose, auth, request/response schema and error cases.
- [ ] Keep all routes under `/api/v1/`.
- [ ] Document pagination/filtering for list endpoints.
- [ ] Identify endpoints needed by the first mobile wireframes.
- [ ] Choose a mock-server approach and record how teammates run it.

## Mock endpoints to prioritize
- [ ] Authentication: register/login response shapes.
- [ ] Courses and document search/list.
- [ ] Paper detail and download metadata.
- [ ] Paper submission and review status.
- [ ] Public verification status.
- [ ] Quiz list, submission and score.

## Run instructions
To be completed after the team chooses the mock-server tool and commits the API contract. Do not invent a command before the tool is selected.
