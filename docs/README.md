# TuStudyHub Documentation

This folder contains the project's **authoritative engineering documents**. GitHub Issues and pull requests are the source of truth for task assignment, progress and review; separate planning templates are intentionally not maintained here.

## Core documents

1. [Project Plan](planning/PROJECT_PLAN.md) — scope, phases, responsibilities, milestones, risks and delivery controls.
2. [Software Requirements Specification](requirements/REQUIREMENTS.md) — functional and non-functional requirements.
3. [System Design Document](design/SYSTEM_DESIGN_DOCUMENT.md) — system structure and technical design.
4. [Architecture](design/ARCHITECTURE.md) — component boundaries and interactions.
5. [Data Model](design/DATA_MODEL.md) — entities, relationships and integrity constraints.
6. [Technology Decisions](design/TECHNOLOGY_DECISIONS.md) — audited technology baseline and open decisions.
7. [REST API Specification](api/API_SPECIFICATION.md) — API routes, access rules and contract decisions.
8. [UX Wireframes and PWA](ux/WIREFRAMES_AND_PWA.md) — screens, navigation and install/offline behavior.
9. [Design System](ux/DESIGN_SYSTEM.md) and [Color Scheme](ux/COLOR_SCHEME.md) — reusable interface standards.
10. [QA Test Strategy](testing/TEST_STRATEGY.md) — verification and acceptance scenarios.
11. [Threat Model](security/THREAT_MODEL.md) — security and privacy risks.
12. [Deployment and Recovery](operations/DEPLOYMENT_AND_RECOVERY.md) — infrastructure, release and recovery procedures.
13. [Responsible AI Use](contributing/AI_USE.md) — acceptable AI assistance and disclosure.

## Document control

- The SRS defines required behavior.
- The Project Plan defines how the team intends to deliver that scope.
- The System Design, Architecture, Data Model and API Specification define the proposed engineering solution.
- The QA strategy defines how requirements are verified.
- The implementation repository and test evidence determine what is actually complete.
- Drafts and individual work products in `Team Draft/` are retained as contribution history; they are not authoritative when they conflict with the documents listed above.

Keep decisions, dates, prices, interview findings and completion claims evidence-based. Remove obsolete drafts only after their useful content has been incorporated and team contribution records are preserved.
